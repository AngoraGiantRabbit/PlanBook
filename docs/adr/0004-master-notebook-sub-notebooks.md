# 单主计划本 + 子计划本两层模型

App 全局只有一个**主计划本**，由若干**子计划本**构成：任务全部落到子计划本上；复盘、复盘设置、自动复盘待办挂在主计划本上（复盘是对整天的总结，不按子计划本分裂）。子计划本有两个独立状态——**显示开关**（是否在计划本页聚合显示）和**活动状态**（同一时刻仅一个，是首页写操作的目标）。每个子计划本有一种颜色，任务块按所属子计划本着色。现有平级多计划本迁移为子计划本，多计划本切换/合并功能退役。

## Considered Options

- **保留多主计划本，下挂子计划本**：否决。层级变成 App→主→子→任务四层，合并、切换、复盘设置都要跨两级考虑，复杂度不成比例。
- **平级计划本 + 聚合视图**（不引入真正层级，当前计划本可勾选聚合显示其它计划本）：否决。"哪些被聚合"和"写到哪"两个语义没有稳定归属，视图概念和数据模型脱节。
- **单主计划本（选定）**：切换场景（工作/学习/旅行）由子计划本显示开关表达；高频的"换写入目标"用首页 chips 浅入口；层级只有两层。

## Consequences

- 数据迁移：现有 notebooks 全部成为唯一主计划本的子计划本（补 parentId/color/显示开关，首个为活动）；tasks 的 notebookId 语义变为 subNotebookId；reviews/review_settings 归主计划本。demo 阶段沿用破坏性迁移。
- 顶栏"计划本切换"弹窗与设置页"合并计划本"退役；设置页"计划本管理"重写为子计划本管理（显示开关、活动指定、颜色、重命名、删除、ICS 导入入口）。
- 计划本页查询聚合所有显示开关打开的子计划本；新建任务/点空白时段预填的目标固定为活动子计划本。
- 桌面小部件与计划本页同源：聚合显示，不引入独立的数据口径。
