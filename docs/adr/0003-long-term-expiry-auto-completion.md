# 长期任务过 DDL 自动完成并消失

长期任务一旦越过 DDL，即视为放弃/过期，由系统自动标记完成（`isCompleted = true`）并从所有视图消失，UI 内不可找回。触发方式为查询时惰性标记：在 `loadTasks` 等查询入口前执行 `UPDATE tasks SET isCompleted=1 WHERE type='LONG_TERM' AND endDate < today AND isCompleted=0`，不依赖后台定时任务。

## Considered Options

- **过期保留可见（变灰/移到底部）**：否决。用户明确表示过期即放弃，不希望它们继续占视觉位。
- **只在待办列表页可见**：否决。会形成「周视图/复盘页看不到、却要切到另一个页面才能看到」的割裂，且违背「不涉及的日子不显示」的初衷。
- **不写 DB，仅查询时过滤**：否决。不写 DB 会让这些任务永远停在 `isCompleted=0`，一旦逻辑变动或导出就会回流。
- **后台定时任务（WorkManager）标记**：否决。鸿蒙/卓易通环境下后台不可靠且耗电；查询时惰性标记足够——用户打开 App 自然收敛。

## Consequences

- 这与 ADR-0001「DAILY 如实反映、不自动标记逾期完成」形成**有意的不对称**：长期目标过期=不再跟进，每日习惯某天没做=只是那天的记录。两者语义不同，故完成策略也不同。
- 过期长期任务在 UI 完全不可见、不可恢复（除非直接改 DB）。这是一个不可逆的语义，文档与 CONTEXT.md 已显式记录，防止日后误改。
- 查询入口（`loadTasks`、`getTasksForDay` 等）需保证在读取前先跑过期标记 UPDATE，否则会出现「已过期但仍显示」的窗口期。
